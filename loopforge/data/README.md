# LoopForge data

All validation in LoopForge uses **measured** Temperature Control Lab (TCLab) data. Synthetic data exists only for algorithm tests and the import demo. It lives in its own folder and is labelled SYNTHETIC wherever it appears.

## Sources

### 1. TCLab step and sine tests: `dowlinglab/pyomo-doe` (used; measured)

|---|---|

| Pinned commit | `d250c5b0625afb35007c075df1e0f7125e74017d` (2026-06-15) |
| DOI | none found for the repository or the data files |
| Licence | BSD 3-Clause, © 2024 Alexander Dowling. The copy is in `samples/LICENSE-pyomo-doe.txt`. |
| Accessed | 2026-11-05 |
| Hardware | TCLab (Arduino heater/TMP36 board), used in the University of Notre Dame process-control course. Their `notebooks/tclab_model.ipynb` describes these files as measured TCLab experiments. `data/tclab_step_test.csv` in that repository is byte-identical to `step_50_run_1`. |
| Columns | `Time` [s], `T1`, `T2` [°C], `Q1`, `Q2` [% heater]. LoopForge uses `Q1 → T1`. |
| Sampling | ≈1.0 s (irregular, 0.98–1.02 s), 901 samples (0–900 s) per run. The 120 s sine run has 900 samples and one 1.99 s gap. |

What each file contains (from inspecting the data itself):

| LoopForge name | File | Input Q1 | T1 at start |
|---|---|---|---|
| step run 1 (**fit**) | `…step_50_run_1.csv` | 50 % from t = 0 | 22.84 °C |
| step run 2 | `…step_50_run_2.csv` | 50 % from t = 0 | 24.13 °C |
| step run 3 | `…step_50_run_3.csv` | 50 % from t = 0 | 23.81 °C |
| sine 300 s | `…sin_5_50_run_1.csv` | 50 ± 50 %, 300 s period | 22.20 °C |
| sine 120 s | `…sin_2_50_run_1.csv` | 50 ± 50 %, 120 s period | 20.91 °C |
| sine 30 s | `…sin_50_50_run_1.csv` | 50 ± 50 %, 30 s period | 19.94 °C |

The periods were measured from the input's zero crossings. The file names do not state them.

**Preprocessing:** none to the values. LoopForge reads `Time`, `Q1` and `T1` and drops `T2` and `Q2`; `tools/build.js` keeps the first five columns when it embeds the files in `index.html`. The heater is assumed **off before t = 0** (`uPre = 0`), because Q1 is already 50 % in the first sample while T1 = T2 = ambient. The logged input is treated as a zero-order hold between samples. T1 is quantised in steps of 0.32 °C (3.3 V / 1024 / 10 mV per °C). This shows up as a sawtooth in the residual plot and is offered as an optional ADC model in the simulator.

**Fit and validation split:** models are fitted on `step run 1` only. The other five records are never used for fitting. For validation, LoopForge simulates each record from its own logged input with the fitted parameters unchanged, taking y0 as the median of the record's first five samples. On imported CSVs, the first 70 % of the record is used for fitting and the last 30 % is held out.

**Why committed:** BSD-3 allows redistribution with the notice retained. The six files total 168 KB. The notice is kept in `samples/LICENSE-pyomo-doe.txt` and in the HTML.

## Reproducing

```bash
python3 data/fetch_data.py                  # downloads to data/raw/ (git-ignored), verifies SHA-256
python3 data/fetch_data.py --check-samples  # verifies the committed copies in data/samples/
```

SHA-256 checksums are listed in `fetch_data.py`. The URLs are pinned to the commit above, so the files cannot change underneath you.

## Synthetic data (`synthetic/`, clearly labelled)

- `synthetic/synthetic_sopdt_step.csv` is generated by `tools/make_synthetic.js` from a known SOPDT model (K = 1.25, τ1 = 45 s, τ2 = 6 s, θ = 3.5 s, input 10 → 40 → 25 %, σ = 0.05). It is used only to exercise the CSV import path in `tests/ui_check.js`. Its header lines say SYNTHETIC.
- The page's "SOPDT benchmark — synthetic" dataset is generated in the browser from K = 0.8, τ1 = 120 s, τ2 = 15 s, θ = 6 s, with noise and 0.32 °C quantisation. It is labelled SYNTHETIC in the UI.

Synthetic data is never used as evidence that the method works on real hardware.
