## Reproducible fetch (run it where the hosts are reachable)

```bash
bash data/fetch.sh --record   # first trusted download: records SHA-256 into data/checksums.sha256
bash data/fetch.sh            # later runs: verify against the recorded checksums
```

* Raw data goes to `data/raw/` (git-ignored). Only `*ambient*` logs are extracted from the ROAD archive.
* The ROAD archive URL is set by `ROAD_URL`, defaulting to the documented DigitalOcean Spaces location. If the authors have moved it, override it: `ROAD_URL=... bash data/fetch.sh`.
* **The checksums have not been recorded by the author, because the download never succeeded.** The script works trust-on-first-use. Review the first download, then commit `data/checksums.sha256`.
* CAN-Modes: download it manually after logging in, place it at `data/raw/can-modes.zip`, then re-run the script to record or verify its checksum.

## Preprocessing (once data is available)

```bash
node tools/analyse_trace.js data/raw/road/<ambient_capture>.log --bitrate 500000 \
     --label measured --source "ROAD ambient <capture name>" \
     --out data/samples/road_<capture>.summary.json --excerpt 30
node tools/build.js          # embeds data/samples/*.summary.json as MEASURED examples
```

`analyse_trace.js` takes a candump `(ts) iface ID#DATA` log (the format the ROAD logs are expected to use; not verified here) or a CSV log, and works out:

* For each ID: median and least-squares period, inter-arrival min/max, the **arrival-time spread** around the fitted periodic grid (an upper bound on jitter plus queuing variation), missing frames, DLC range and a periodic/aperiodic flag.
* The bitrate, inferred from back-to-back frames (lower bound on bit time). Pass `--bitrate` when the dataset documents it; ROAD's bitrate was not verified here.
* Observed bus load with **exact** bit stuffing per logged payload. The CRC-15 and stuffed bit stream are rebuilt bit by bit.
* A message set built from the trace. **Deadlines are assumed equal to the measured period**, because the data has no deadlines. It is analysed twice: with release jitter assumed 0, and with jitter equal to the measured spread (conservative and partly circular).
* A comparison: observed load against the predicted no-stuffing and worst-case range, and observed spread against the model bound `R_m − C_m,min` for each ID. A spread above the bound is reported as **DISAGREES**.

Commit only small excerpts, and only where the ROAD licence allows redistribution. The `--excerpt` option keeps the first N seconds.

## Synthetic data (`data/synthetic/`) — SYNTHETIC, not measured

| File | What it is |
|---|---|
| `demo_vehicle.dbc` | An original, unbranded 29-message, 500 kbit/s network (10 ECUs, 3 × 29-bit IDs), made by `tools/make_synthetic.js`. It has two **planted, labelled errors**: `DIAG_Planted_Error` (overlapping signals that run past the payload) and `ESC_ParkBrakeCmd` (a 4 ms deadline on a low-priority ID). |
| `demo_vehicle.log` | A 30 s candump trace **generated by the CANProof simulator** from that DBC, with random offsets, random release jitter within `GenMsgJitter`, exact stuffing of generated payloads, and 1 µs timestamps. |
| `demo_vehicle.summary.json` | The output of `analyse_trace.js` on that log, with the full 30 s excerpt, embedded in the page. |

The trace comes from the same model, so agreement with the analysis is **expected and is not validation**. It is useful only because the ground truth is known. The tests use it to check that measurement recovers the DBC periods, that the bitrate inference returns 500 kbit/s, that observed load falls in the predicted range, and that the J = 0 model disagrees **only** for messages that really have injected jitter (3 of 29 do). Regenerate it with `node tools/make_synthetic.js` (deterministic seed).
